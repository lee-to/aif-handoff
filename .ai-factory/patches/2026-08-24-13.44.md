# Clear stale QA Check output when a rerun starts

**Date:** 2026-08-24 13:44 MSK
**Files:** `packages/data/src/index.ts`, `packages/api/src/__tests__/runQaRoute.test.ts`, `packages/web/src/__tests__/TaskQA.test.tsx`, `.env.example`
**Severity:** medium

## Problem

A failed QA Check rerun changed the lifecycle status to `error` but left the previous successful report visible. The report could therefore be mistaken for evidence from the failed run. The QA feature-flag comment also omitted the new QA Check route and automatic trigger.

## Root Cause

The atomic QA Check claim updated only `qaCheckStatus`. Outputs belonging to the previous run were cleared later only on successful paths, so an exception before report persistence preserved stale evidence.

## Solution

The atomic claim now clears the previous report and Playwright preflight result in the same update that marks the new run as `running`. A route regression starts with an existing report, forces the rerun to fail, and verifies that no stale output remains. The environment example now documents both QA endpoints and automatic triggers.

## Prevention

- Reset run-specific outputs atomically when claiming a new lifecycle run.
- Cover rerun failures with pre-existing successful output in integration tests.
- Keep feature-flag examples synchronized with every route and automatic path they gate.
