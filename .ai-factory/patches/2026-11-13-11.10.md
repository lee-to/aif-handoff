# Bound Swarm run history before loading it

**Date:** 2026-11-13 11:10
**Files:** packages/api/src/services/swarm.ts, packages/api/src/services/swarmContract.ts, packages/shared/src/swarm.ts, packages/web/src/components/swarm/SwarmPanel.tsx, packages/web/src/components/swarm/SwarmRunDetail.tsx
**Severity:** medium

## Problem

Historical snapshots exceeding 10 MB made run listing return 502 and blocked creation. Integration showed zero pending for a submitted task awaiting approval.

## Root Cause

List normalization happened after downloading every full snapshot. Create reused that unbounded list as a project check. Pending integration counted artifacts, although the native Runtime creates a successful artifact only after integration.

## Solution

Use native SQL-projected scalar summary pages with keyset cursors and global filters. Check the authenticated project identity before create and look up native create idempotency by ID. Count submitted tasks as pending, verifying tasks as in progress, and approvals separately. Keep successful artifacts integrated. Update fixtures to represent distinct submitted and completed tasks.

## Prevention

- Bound storage reads and wire payloads before normalization; a response-size cap alone is not pagination.
- Test history exceeding the consumer body limit, tied cursor timestamps, filters on later pages, empty foreign projects and create without a history scan on SQLite and PostgreSQL.
- Derive workflow counters from authoritative task states and test submitted/verifying/completed tasks without artifacts.
