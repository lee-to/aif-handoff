# Gate Verify remediation and refresh security dependencies

**Date:** 2026-11-05 19:11
**Files:** Verify/coordinator execution, environment configuration and tests, package manifests and lockfile, configuration docs
**Severity:** high

## Problem

PR 189 enabled a new file-mutating fixer for existing Verify tasks by default. Its stricter gate parser and timeout handling also changed legacy behavior. The CI production security audit failed on vulnerable runtime dependencies.

## Root Cause

- A finite retry limit was mistaken for a rollout gate; the new execution path needed a separate off-by-default switch.
- Compatibility checks covered fixer execution but did not preserve first-gate parsing, missing/malformed gates, branch/report ordering, and timeout recovery together.
- Exact dependency overrides retained vulnerable releases, and MCP still used an unpatched Zod 3 dependency.
- MCP settings tests assumed the ambient default database path, preventing validation against an isolated database.

## Solution

- Added validated `AIF_AGENT_VERIFY_REMEDIATION_ENABLED=false`, Turbo passthrough, documentation, and environment fixtures.
- Preserved legacy Verify behavior while disabled and tested the enabled/disabled paths with both attempt-recovery states. Regression tests first reproduced four rollout failures.
- Updated affected production packages and the high-severity Vite development advisory; moved MCP to patched Zod 4, which its SDK supports. Kept unrelated dependency versions intact.
- Isolated settings fixtures from the caller's database environment and verified a clean install with the CI Node 22 runtime.

## Prevention

- Ship new mutating runtime invocations behind an explicit off-by-default flag, independently of loop limits.
- Test the complete disabled path against previous behavior, including parser selection and error recovery; propagate every documented AIF flag through Turbo.
- Review lockfile changes after dependency tooling, verify exact pins match resolved entries, and run the same production audit as CI.
- Explicitly control environment values assumed by test fixtures so isolated validation remains reproducible.
