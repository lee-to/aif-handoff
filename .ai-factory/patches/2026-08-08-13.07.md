# Remove temporary issue markers from GitHub workflow logs

**Date:** 2026-08-08 13:07 MSK
**Files:** packages/agent/src/githubWorkflow.ts, packages/api/src/routes/github.ts, packages/api/src/services/github.ts
**Severity:** low

## Problem

Production log messages added during the issue 154 review follow-up retained temporary ticket-prefixed debug markers. The operational events and structured fields were useful, but the review cleanliness gate rejected the developer-only prefixes.

## Root Cause

The bug-fix workflow required traceable diagnostic logging during implementation, but the temporary issue identifiers were not removed before the production follow-up was committed.

## Solution

Removed only the temporary prefixes from the four affected messages. Log levels, structured context, event wording, feature-flag behavior, and CI aggregation behavior remain unchanged.

## Prevention

- Keep durable operational messages free of temporary ticket or debugging prefixes before commit.
- Preserve structured fields and stable event wording when cleaning up implementation-time diagnostics.
- Run a production-source marker scan during review follow-ups.
