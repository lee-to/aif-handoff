# Auto-queue commit gate review fixes

## Problem

The auto-queue commit gate serialized every Git-backed project without task
worktrees, including projects that did not use auto-queue. A scheduled
auto-queue task could also be claimed from an already dirty shared worktree and
later commit unrelated changes. The behavior had no rollout flag, making the
new gate active for all installations immediately.

## Root Cause

Coordinator serialization was derived from Git/worktree capability alone
instead of the project's auto-queue mode. Scheduled task promotion did not
validate the effective worktree before claiming the task. The commit gate was
introduced without an environment-controlled compatibility boundary.

## Solution

- Added `AIF_AGENT_AUTO_QUEUE_COMMIT_GATE_ENABLED`, defaulting to `false`.
- Scoped shared-worktree serialization and commit-state preparation to
  auto-queue projects while the flag is enabled.
- Deferred scheduled auto-queue tasks when their effective worktree is dirty.
- Preserved legacy parallel execution for non-auto-queue projects.
- Added regression coverage for dirty scheduled worktrees, project concurrency,
  environment parsing, and Turbo environment propagation.
- Consolidated repeated Git test-repository setup in a shared test helper.

## Prevention

Risky coordinator behavior must ship behind an off-by-default feature flag.
Concurrency predicates must include the workflow mode they protect, and any
workflow that may create a commit must reject a dirty worktree before task
ownership changes.
