# Reconcile orphaned GitHub issues and delayed pull requests

**Date:** 2026-08-08 21:54 MSK
**Files:** packages/api/src/routes/github.ts, packages/api/src/__tests__/github.test.ts
**Severity:** medium

## Problem

GitHub sync recreated a task for a closed issue when its persisted GitHub link no longer referenced a task. It also skipped pull-request discovery for already-imported issues, leaving a task in backlog even after a closing pull request appeared.

## Root Cause

The sync treated the existence of a GitHub link row as equivalent to the existence of a task. Pull-request discovery was likewise restricted to issues without a link row, although links can predate their closing pull requests.

## Solution

Apply issue eligibility whenever the link has no task, discover a closing pull request for any eligible issue without a stored PR, and move the linked task to `done` through the existing audited transition path.

## Prevention

- Keep source-link persistence separate from task-lifecycle decisions.
- Cover delete-and-resync plus delayed-PR discovery in one regression test.
