# Preserve rollout compatibility and refresh linked chat PR evidence

**Date:** 2026-11-05 20:51
**Files:** shared/env.ts and types.ts; data/index.ts; API chat, github and settings routes; web App and ChatPanel; related regression tests and configuration docs
**Severity:** medium

## Problem

The chat workspace was enabled unconditionally. Session creation could discover runtime history in an existing flow, and New chat persisted before the first message. Linked task rows omitted the loaded PR state, checks, review and objective title. GitHub evidence-only sync/publication writes did not invalidate cached workspaces.

## Root Cause

The feature was checked with its new behavior enabled, without an explicit legacy compatibility path. Consumer-side task event invalidation was added without tracing every producer of github_issues evidence. The workspace read model included fields the panel never rendered.

## Solution

- Default AIF_CHAT_THREAD_WORKSPACE_ENABLED to false and expose the cached server setting to the UI. Gate workspace routes, runtime discovery, session deduplication/status responses and updates, and the panel's persistence/claim controls; preserve message routes and additive storage.
- Show objective titles and PR/checks/review fields with existing badges and wrapping rows.
- Broadcast existing task:updated events after GitHub sync/publication writes when enabled, including changes that leave task stage unchanged. Keep stable debug logging for disabled routes and evidence notifications.
- Before production edits, rollout, panel and evidence-only sync regressions failed. The original evidence test setup used a helper that intentionally strips stage updates; replacing it with the actor-aware transition reproduced the missing broadcast. Those same checks pass after the fix. Add real database off-path and settings tests, and verify both rollout states and themes in the browser.

## Prevention

- For a default-off rollout, trace existing behavior through request validation, persistence, DTOs and UI actions; hiding controls alone is insufficient.
- Trace aggregate read models back to every writer and forward through notification, cache invalidation and visible fields. Test an evidence-only update with unchanged task stage.
- Keep env schemas, Turbo passthrough, settings contracts, typed fixtures and docs synchronized. Test flag-off compatibility as well as opt-in behavior.
