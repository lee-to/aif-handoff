# Participant account controls and overlay layout fixes

**Date:** 2026-07-31 18:30 MSK
**Files:** `packages/data/src/participants.ts`, `packages/api/src/routes/auth.ts`, `packages/web/src/components/participants/ParticipantMenu.tsx`, `packages/web/src/components/ui/form-dialog.tsx`, `packages/web/src/components/ui/select.tsx`, related tests and participant documentation
**Severity:** medium

## Problem

Participant creation actions touched the final role field, role menus expanded inside the participants table and caused scrolling, and signed-in members had no way to change their password.

## Root Cause

The shared form dialog footer had no separation from form content, the shared select rendered its menu inside the nearest overflow container, and local authentication only exposed administrator password resets.

## Solution

- Added consistent spacing before shared form dialog actions.
- Portalled shared select menus to the document body while preserving trigger width, outside-click handling, Escape behavior, and listbox semantics.
- Added an authenticated password-change flow that verifies the current password, atomically replaces the hash, keeps the current session, revokes other sessions, and records an audit event.
- Added participant UI, API, and data regression coverage plus user-facing documentation.

## Verification

- Playwright confirmed admin/member account menus, both dialog layouts, password submission, and that opening a table role selector does not change the table scroll height.
- Pencil contains the four participant interface states; its layout scan reports no problems.
- Web, API, and data targeted tests, lint, and builds passed; the full web suite passed with 723 tests.
- `npm run ai:validate` passed format, lint, all tests, coverage, and build, then stopped at the existing perf harness because its unauthenticated requests receive `401` in Participants Mode. The same auth-harness mismatch reproduced on an isolated temporary database; protocol sync and package checklists passed when run separately.

## Prevention

- Render overlays outside scroll containers and keep their semantic roles covered by shared-component tests.
- Keep credential changes in the data boundary with constant-work verification, compare-and-swap updates, session revocation, audit logging, and API rate limiting.
- Use the shared form dialog footer spacing for participant forms.
