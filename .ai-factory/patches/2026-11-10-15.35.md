# Align Swarm control plane with its Runtime

**Date:** 2026-11-10 15:35 UTC
**Files:** Swarm API contract/service/routes, shared inputs, web creation/controls, fixtures, docs and live probe
**Severity:** high

## Problem

A real Runtime returned valid native runs and SSE events, but Handoff rejected reads
with `502 swarm_contract_error`. Creation failed with `Unknown Swarm setting`.

## Root Cause

Consumer-only fixtures encoded a proposed API as though it were the upstream wire
contract. They could not reveal independent implementation drift. An empty run list
also passed while every nonempty response failed.

## Solution

Validate native wire objects separately and normalize them into browser DTOs. Match
returned Runtime project paths before exposing state. Send native creation fields
and header-only idempotency keys; validate native command responses. Reconcile an
already-applied approval before retrying a terminal run. Expose actual token/agent
limits, required checks and supported providers/decisions in the UI.

## Prevention

- Keep upstream fixtures separate from browser fixtures.
- Test nonempty state, creation/control, SSE replay and response-loss retries against
  the actual independently built Runtime, using a disposable project.
- Do not assume a project query parameter enforces isolation. Document deployment
  binding when an upstream empty list has no project identity.
- Model inference remains separate from transport/contract verification.
