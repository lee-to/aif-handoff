# PR 169 security review fixes

**Date:** 2026-08-03 11:53 MSK
**Files:** `packages/api/src/routes/tasks.ts`, `packages/api/src/middleware/`, `packages/api/src/ws.ts`, `packages/data/src/taskOwnership.ts`, `packages/mcp/src/env.ts`, `packages/mcp/src/server.ts`, perf harnesses, related tests and security documentation
**Severity:** high

## Problem

PR review found task mutation IDOR paths, unauthenticated HTTP MCP access outside Participants Mode, a task handoff lock race, unsafe internal broadcast authentication, overly strict cross-host CSRF validation, session-revocation event leakage, and participant-mode contamination of performance checks.

## Root Cause

Several older compatibility paths bypassed the newer participant authorization boundary. Task handoff checked locks before its atomic update, HTTP MCP tied authentication to an unrelated feature flag, and internal broadcast development access trusted client-controlled proxy headers.

## Solution

- Required administrators or active assignees for generic task updates, plan sync, QA dispatch, and position changes.
- Required timing-safe bearer authentication for every HTTP MCP request while keeping `/health` public.
- Added lock availability to the handoff compare-and-swap update and classified a raced lock as `locked`.
- Removed proxy-header broadcast bypasses, used timing-safe internal-token comparison, and targeted session-revocation disconnects to the affected participant.
- Validated browser requests against the exact configured origin without incorrectly requiring the UI and API hostnames to match.
- Forced perf/load dev stacks into anonymous compatibility mode so local participant settings cannot turn measurements into `401` checks.

## Verification

- Added API, data, and MCP regressions for the reported authorization, lock-race, origin, proxy-spoofing, and HTTP-token cases.
- `PARTICIPANTS_MODE_ENABLED=true npm run ai:perf` passed all 5 browser checks.
- `npm run ai:validate` passed formatting, lint, all package tests, coverage, build, browser perf, all 3 k6 load scripts, protocol sync, and checklist gate.

## Prevention

- Keep participant authorization at route mutation boundaries and lock invariants inside atomic database predicates.
- Treat every network transport as authenticated independently of optional UI modes.
- Never derive trust from client-supplied forwarding headers without a trusted proxy boundary.
