# Stabilize GitHub project creation paths and selection

**Date:** 2026-08-14 09:52 MSK
**Files:** packages/api/src/repositories/projects.ts, packages/api/src/__tests__/projects.test.ts, packages/web/src/hooks/useProjects.ts, packages/web/src/__tests__/useProjects.test.tsx
**Severity:** medium

## Problem

Native development resolved a relative `PROJECTS_DIR` from the API package working directory, so GitHub repositories were cloned under `packages/api`. After creation, the UI could also return to the projects overview instead of opening the new project.

## Root Cause

Managed path resolution depended on `process.cwd()`, which Turbo sets to `packages/api`. The create mutation invalidated the projects query without first adding its response to the cache, so selection validation could reject the new project while the cached list was stale.

## Solution

Resolve relative managed directories from the existing monorepo-root helper, and synchronously add the created project to the React Query cache before invalidating it for reconciliation.

## Prevention

- Test relative native clone destinations independently of the process working directory.
- Keep mutation responses in cache before selecting newly created entities.
