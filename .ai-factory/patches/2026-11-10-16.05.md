# Bound Swarm run-list work

**Date:** 2026-11-10 16:05 UTC
**Files:** packages/api/src/services/swarm.ts, swarmContract.ts and Swarm route tests
**Severity:** low

## Problem

The polled run list read the same project once per run and normalized detail
collections that it never returned. PR 193 review identified the unnecessary work.

## Root Cause

The initial native mapping reused the entire snapshot path to obtain `.run`.

## Solution

Resolve the configured project once per list request and normalize only summaries.
Reuse the summary mapper inside full snapshots and retain per-run project checks.
The regression check reproduced two lookups for two runs before the fix and now
requires one lookup regardless of list size.

## Prevention

- Separate list projections from detail projections when their traversal costs differ.
- Keep database lookup counts bounded for periodically polled list endpoints.
