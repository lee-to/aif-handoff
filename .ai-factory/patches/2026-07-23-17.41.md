# OpenRouter unrestricted effort discovery follow-up

**Date:** 2026-07-23 17:41 MSK
**Files:** `packages/runtime/src/modelEffort.ts`, `packages/runtime/src/adapters/openrouter/api.ts`, `packages/runtime/src/adapters/openrouter/index.ts`, `packages/runtime/src/adapters/TEMPLATE.ts`, `packages/runtime/src/__tests__/openrouterApi.test.ts`, `packages/runtime/src/__tests__/modelEffort.test.ts`, `docs/providers.md`
**Severity:** medium

## Problem

OpenRouter uses `reasoning.supported_efforts: null` to declare that a model accepts every gateway effort value. Model discovery recorded only `supportsEffort: true`, so central validation fell back to the stable rollout allowlist and rejected gateway-only values such as `max` and `none`. The adapter template also implemented `listModels()` while leaving `supportsModelDiscovery` disabled, making the example method unreachable through normal capability checks.

## Root Cause

The discovery parser treated `null` as a boolean capability instead of an unrestricted gateway enum. The distinction between provider-discovered values and the off-by-default fallback list was therefore lost before registry validation and UI rendering. The template capability and method were updated independently and drifted out of sync.

## Solution

- Added a dedicated OpenRouter gateway effort list containing `max`, `xhigh`, `high`, `medium`, `low`, `minimal`, and `none`.
- Expanded `supported_efforts: null` into that explicit list during model discovery and emitted a structured `[FIX:openrouter-effort]` debug record.
- Kept the existing OpenRouter fallback allowlist unchanged so flag-off behavior remains stable.
- Enabled `supportsModelDiscovery` in the adapter template because its sample `listModels()` implementation is present.
- Documented the OpenRouter `null` semantics and added regression coverage for discovery parsing plus central validation.

## Verification

- The OpenRouter regression test failed before the implementation and passed afterward.
- `@aif/runtime`: 869 tests passed; lint and TypeScript build passed.
- Runtime coverage passed at 85.56% statements, 72.73% branches, 90% functions, and 86.64% lines.
- Repository `ai:validate` reached the full test phase but stopped on the unrelated `@aif/api` node-server-v2 WebSocket integration test (`upgradeWebSocket is not a function`). No API files are changed by this fix.

## Prevention

- Preserve provider distinctions such as omitted, empty, explicit, and unrestricted capability metadata until the runtime-neutral model contract is built.
- Keep rollout fallbacks separate from dynamically discovered provider enums.
- When a template implements a capability-gated method, enable the corresponding capability in the same change.
- Cover both the discovery-on behavior and the stable discovery-off fallback in regression tests.
